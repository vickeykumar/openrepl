Genie

How to use Genie

Genie is the AI helper in the editor. It reads your code and your terminal, answers questions about them, and, in Agent mode, does a task for you in your workspace. This guide takes five minutes.

Start in a minute

  1. Open Genie. Press Ask Genie in the top bar. The pin in its header keeps it beside your code.
  2. Ask. Type a question and press Enter (Shift Enter for a new line). Genie sees your editor code and the latest terminal output, so you can ask why something fails without pasting anything.
  3. Use the answer. Code in an answer has Insert and Replace buttons. A change to your code is shown as a diff and applied only when you accept it.

Give it your code

Point Genie at exactly what it should look at.

  • Select code and right-click: Explain answers in the panel. Fix problems, Add comments and Write tests show their change as a diff with Accept and Reject for each part.
  • Add to Genie chat: right-click a file or folder in the Files panel, or select code or terminal text and press Ctrl Shift L (Cmd Shift L on a Mac). Each addition is a chip above the message box.
  • Type # and a few letters of a name in the message box to pick a file from the list.

Chat or Agent

  • Chat answers questions. Everyone can use it.
  • Agent carries out a task in steps: it writes in the editor, switches the language, presses Run and reads the output. It is for signed-in users: switch from Chat to Agent beside the Send button.

Each mode remembers its own model, so choosing a model in Agent does not change your Chat model.

When a task is done, its card folds to one line when you write again ("Done · Changed 3 files · 7 steps · 14 s"); click the line to see the steps.

Agent mode, safely

Describe a task, for example "write a program that prints ten squares and run it". The card starts with a plan that the agent ticks off as it goes.

  • It asks first before it changes your editor, switches the language, runs your program or uses the terminal: Allow once, Allow for this session, or Deny.
  • You see every change as a diff, applied only when you accept it.
  • Undo this task at the end of the card puts everything back as it was, unless you changed it since.
  • Review is a bar above the chat box that counts the files the task changed and, when it ends, lists them (changed, new, renamed, moved, deleted, and what commands made). Click a file to see it in the editor with the changes marked; Keep or Undo, and the row goes. Undo all asks first.
  • When it gets stuck (three failures in a row, six steps that change nothing, or, in a long stretch, most steps used with nothing changed) Genie pauses and offers Keep going, a hint from you, a stronger model if the site has one, or Stop.
  • If the page closes during a task, the chat offers Resume this task or Discard when you come back. Resume carries on from your files as they are now.
  • Riskier things (risky terminal commands, deleting, renaming and moving, closing a terminal tab) are asked every time. A delete moves to a Trash folder of your workspace.
  • When a task uses its steps it pauses and asks. Carry on continues the same task.
  • Notes about your project: a file named GENIE.md in your workspace tells it how to run the project, the style and what not to touch. Put the important lines first: only the first part is read.

Chats and tabs

Each chat is a tab above the conversation, saved in your own workspace, so it comes back after a reload and follows your workspace. The list button shows every chat; you can rename, close and reopen them, and export a chat as Markdown.

The search box in the list looks in the titles and in what was said, with Starred, Chat and Agent buttons to narrow it. Star a chat to keep it first in the list and out of Delete all. It is kept in the chat's own file, and you can star 20.

While the panel has the focus: Alt T a new chat, Alt W close, Alt ← → move between chats, Alt 1 to 8 go to a chat, Alt H all chats.

Models and requests

  • Choose the model with the chip beside Send. Star a model to keep it in your list, open Other models for the rest, or search (press /).
  • Some models think first and have an effort setting; some are free and share a daily allowance. A small model gets a note in Agent mode, because Agent works best with a stronger one.
  • Auto, at the top of the list when your site offers it, picks a small model for plain questions and a stronger one for changes, files and tasks. The chat says which one answered, and Use a stronger one asks again. Choosing a model yourself turns Auto off.
  • Each message, and each Agent task, uses one request. The line under the message box shows how many you have left and when they refill; click it for the details. Signed-in users get more.

Handy things

See what Genie sees

Click Context in the header of the panel. It lists each part that goes with your next message, with its size: the editor, the terminal, the Preview page, your project notes, this chat and what you attached. A grey line says why something is not sent. It shows sizes and names only, never the text.

Type / for commands

Type / at the start of the message box to list the commands, each with a line about it. Use ↑ ↓ and Enter or Tab, or click one; Esc closes the list. /context opens the list above, /tour shows the tour again, and /remember adds a note for Genie.

Teach Genie about your project

Type remember: and a sentence, or use /remember, for example "remember: indent with tabs". It is added to a file called GENIE.md in your workspace, and every Agent task starts with it. Open the file to change or delete a note. No model is asked, so it costs no request.

Skills and plugins

Skills teach Genie how to do a kind of task, and plugins bring skills made by others. Skills and plugins has the whole guide, with pictures.

The tour

The first time you open Genie, a short tour points at Chat and Agent, the model picker, the starter chips and the box. Esc or Skip ends it. Type /tour to see it again.

Skills and plugins

A skill is a short text file that tells Genie how to do a kind of task: fix merge conflicts, write release notes, review code the way your team does. You use one by typing its name after a slash. A plugin is a folder of skills made by someone else, and you add one with /add-plugin.

Nothing in a skill or a plugin runs by itself. A skill is words for Genie to follow, and whatever it asks Genie to do still goes through the same permission cards, limits and Review as any task. In the pictures below the IDE is maximized and Genie is pinned beside it.

1. Pick a skill from the / menu

Type / in the message box. The menu lists the commands of the panel first, then the skills in three groups: Genie (the built-in ones: explain, review, test, fix-merge-conflicts and pr), Your skills for this workspace, and Plugins with the name of the plugin beside each. A small tag says whether a skill answers in chat or runs a task as an agent, and a skill that takes words after its name shows what they are, like "the file or branch".

Keep typing to narrow the list, use ↑ ↓, and press Enter or Tab to pick. The name goes into your message and you carry on with your own words. A skill can also come in the middle of a sentence: after a space, "please write /release-notes for 2.0" opens the menu with the skills only. A slash inside a path or a web address, like /usr/bin/python, never opens it. A name that is not a skill stays plain text, and the message is never refused.

Every skill your message names also shows as a chip above the box, next to the chip of the file you are working on, with its tag (chat or agent). The name stays in your text. The × on the chip takes the name out again, and the chip goes when you send.

2. A chat skill answers in Chat

A skill with the chat tag, like /release-notes, gives Genie its instructions for this one message. Your message stays as you typed it, and the text of the skill goes along with it. Genie reads a skill's text only when you use it, so having many skills costs nothing until one is needed. If you are in Agent mode when you send a chat skill, it answers in Chat and the mode you had is kept for next time. You can name two skills in one message: both are given, in the order you wrote them.

3. An agent skill starts a task

A skill with the agent tag, like /fix-merge-conflicts, starts an Agent task with the skill's steps. The panel switches to Agent mode for you; agent skills are for signed-in users, like Agent mode itself. The task asks the usual cards: here it asks before it looks at your files, and you can Allow once, Allow for this session or Deny. Review, Undo this task and the step limit work as they always do.

A skill can limit what a task may do. If its header has an actions line, the task may use only those actions (and always reading files, asking for more tools and finishing). Any other action is refused and Genie is told which are left. A skill can only narrow the list, never add to it or skip a card. Without an actions line nothing is limited. When you do not name a skill, Genie still sees the names and descriptions of the skills in your workspace, in your plugins and in the plugins your admin put on for everyone, at the start of a task, and can read one itself when the task fits it; it says so in its plan.

4. Write your own skill

A skill is a file in the hidden folder .genie/skills of your workspace, named after the skill: .genie/skills/fix-merge-conflicts.md. Turn on Show hidden files in the Files panel to see and edit it like any other file. It travels with a fork or a snapshot of the workspace. The file starts with a header between two lines of three dashes, then the steps in plain words:

---
name: release-notes
description: Write the notes for a release
mode: chat
args: the version
---
Write release notes: one line for each change, newest first.
Use plain words. Do not invent changes that are not in the code.
  • name and description are required. The name is lower case letters, digits and dashes, starting with a letter, and the file is called name.md. The description is one line of at most 160 characters: it is what the menu and Genie show.
  • mode is chat (the default) or agent.
  • args is a hint shown in the menu about the words you add after the name.
  • actions is optional, for example [files_read, files_search, editor_replace]. It limits an agent task to those actions, as described above.
  • effort (low, medium or high) is optional. If you use the skill when your own effort is higher, that one message or task is sent with the lower effort, which is quicker and costs less. It never raises your effort, and a skill that names none leaves yours alone.
  • A skill is at most 16 KB, a workspace keeps up to 100 of its own, and a few names belong to the panel itself (context, tour, remember, add-plugin, save-skill). A file with a mistake in its header is left out of the menu, so if a skill does not show, check its header.

The quickest way to make one: do a task well, then type /save-skill and a name, for example /save-skill release-notes. Genie writes the file from what it just did, shows it to you, and you read and edit it before you rely on it. This is an Agent task, so it needs you to be signed in.

5. Add a plugin from the catalogue

Type /add-plugin. The dialog lists the plugins the site ships (Code review kit, Git helper, Docs writer), each with its skills. Press Install and a card shows what the plugin brings before anything is written: every skill with its mode and the actions it uses (the ones that can change things, like bash and writing files, are in yellow), and View the files to read each one. Then press Install again. The plugin goes into .genie/plugins/<name> of your workspace and its skills appear in the / menu under Plugins, with the plugin's name beside them. If the plugin brings notes (plain Markdown files, like a review checklist), the card lists them by title. Genie sees the titles at the start of a task and reads a note when the task is about what its title says; a note is never pasted into every message.

The Installed tab lists what you have. Update shows what changed in each file before it applies, and Remove deletes the plugin's folder and nothing else; the skills you wrote are never touched. An admin can also switch a plugin on for everyone, and then its skills are in every user's menu without an install.

6. Add a plugin from a link

If your admin allows it, the dialog also has Add from a link. Paste a GitHub repository (like https://github.com/acme/genie-review-kit), a folder in one (/tree/main/folder) or a link to a .zip file and press Look. Without the admin's switch the dialog says to ask an admin.

The Genie server fetches the link, never your browser, and keeps only text: the plugin's plugin.json, its skill files and its notes. Everything else in the package is left out and counted. The card then says Not from the catalogue, shows the link in full and lists every skill. Install stays off until you tick that you read the skills. If the plugin changes between the card and the install, the install is refused and you look again.

Some things are never installed from a link: a plugin that asks for a connection to an outside service, a package bigger than 2 MB or with more than 40 skills, and a link that is not https or that points inside a private network. Each person may look at up to 12 links an hour, and the server log records which links were fetched.

Make your own plugin

A plugin is a folder, or a GitHub repository, with this shape. Anything else in it is left out when someone installs it.

my-plugin/
  plugin.json          name, title, version, description, author
  skills/review-it.md  one file for each skill, as described above
  knowledge/checklist.md   optional notes, plain Markdown, at most 8 KB each

plugin.json is a small JSON file, for example { "name": "my-plugin", "title": "My plugin", "version": "1.0", "description": "Review skills for my team", "author": "me" }. The name is lower case letters, digits and dashes. A plugin needs at least one skill, may have up to 40 skills and 20 notes, and the file name of each skill has to match the name in its header. Put it on GitHub and paste the link in /add-plugin if your admin allows links, or share the link with your team.

Who can use what

  • Signed-in users have all of it: their own skills, plugins, agent skills and /save-skill.
  • Guests have the built-in chat skills (explain, review and pr) and nothing that is saved in a workspace. Someone who joined a shared session sees the same short list.
  • Admins choose in Site settings, under Agent, "Skills and plugins": switch it all off, allow plugins from a link (off by default), and put catalogue plugins on for everyone. Under "Plugin installs" the admin sees every install, update and removal for the last 90 days: who (the account id), which plugin and version, and where it came from, with a link in full.

On a phone

Genie is the third tab of the switch above the workspace, beside Editor and Terminal, and fills the screen there. A dot on the tab shows when it is working or needs you; leaving the tab does not stop it.

Practice coach

On the practice page Genie works as a coach: it gives hints without handing you the answer, reviews your solution and explains its complexity. Only Explain is offered in the right-click menu there.

Keys

Press ? outside a text field for the list of all the keys. The ones for Genie: Enter sends, Shift Enter starts a new line, / at the start of the box lists the commands, Ctrl Shift L adds the selection to the chat, and the Alt keys above move between chats.

Questions

Are my chats kept?

Yes, in your own workspace. You can delete them from your profile page.

What is a skill?

A text file in .genie/skills of your workspace that Genie follows when you type its name after a slash. It can only narrow what a task may do, never add to it. /add-plugin installs skills made by others.

Does Genie keep working if I close its panel?

Yes. An answer or an Agent task carries on while the panel is closed.

What does Genie see?

Your editor code and the latest terminal output, and the files you add to the chat. You can click the dashed chip to stop it looking at the editor. The Context button in the panel's header lists each part with its size, so you can see exactly what goes with the next message.

Can it remember things about my project?

Type remember: and a sentence in the box. It is added to GENIE.md in your workspace, and every Agent task starts with it.
