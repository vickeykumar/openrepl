Install apps and packages

OpenREPL offers two ways to add software: the App Store makes a curated app available to your terminals, while a package manager in Bash installs a copy in your workspace or project. Use the App Store when you want a package integrated with its REPL; use a terminal package manager for a project-local dependency or command-line tool.

Install from the App Store

  1. Sign in, then open Apps in the editor toolbar or visit the App Store.
  2. Search for a library or tool. Press Install for an app you can add, or Request when administrator approval is needed.
  3. When the install finishes, turn its switch on under My apps.
  4. Open a new terminal tab. For a terminal that is already open, run the activation line shown under My apps.

App Store installs are managed by the server and shared across users; the switch controls whether your own terminals use them. The catalogue includes Python libraries and tools from conda-forge, Node packages from npm, Bash tools from Ubuntu packages, and Go modules, Java jars and Rust crates from server-managed mirrors.

[python3]$ python3 -c "import requests; print(requests.__version__)"
2.34.2
[node]$ node -e "console.log(require('lodash').chunk([1,2,3], 2))"
[ [ 1, 2 ], [ 3 ] ]
[bash]$ rg --version
ripgrep 13.0.0

Before installing from Bash

Direct downloads from a terminal need Internet for REPLs enabled by the site administrator. Signed-in non-admin terminals receive the proxy settings when it is enabled. Guests and admin terminals do not use this proxy. App Store downloads are made by the server and do not depend on a terminal's network access.

Terminal installs are local to your workspace or project; they are not shared App Store apps. Package build and download caches use the terminal's scratch area when available. Watch the Scratch and Workspace meters for large installs.

conda-forge with Pixi

Use Pixi for a project-local conda-forge environment. Run its Python through pixi run; it is separate from the regular OpenREPL Python terminal. To make a library available directly in that terminal, use the App Store instead.

root@bash:~# mkdir conda-demo && cd conda-demo
root@bash:~/conda-demo# pixi init
root@bash:~/conda-demo# pixi add --channel conda-forge numpy
root@bash:~/conda-demo# pixi run python -c "import numpy; print(numpy.__version__)"
2.x.x

Python packages with pip

Outside a virtual environment, pip installs in your user area, not the protected system Python folders. Inside a virtual environment, activate it first and then install normally.

root@bash:~# pip install requests
root@bash:~# python3 -c "import requests; print(requests.__version__)"
2.x.x
root@bash:~# python3 -m venv .venv
root@bash:~# source .venv/bin/activate
(.venv) root@bash:~# pip install requests

Node packages with npm

Install a library into your project folder and import it from Node. Global npm command-line tools install into your workspace and are added to PATH.

root@bash:~# mkdir node-demo && cd node-demo
root@bash:~/node-demo# npm init -y
root@bash:~/node-demo# npm install lodash
root@bash:~/node-demo# node -e 'console.log(require("lodash").chunk([1,2,3], 2))'
[ [ 1, 2 ], [ 3 ] ]
root@bash:~/node-demo# npm install -g cowsay
root@bash:~/node-demo# cowsay "hello from OpenREPL"

Go modules and command-line tools

Use go get inside a Go module to add a library to go.mod. Use go install with a version to install a command into ~/go/bin. On current Go, go get does not install command-line tools.

root@bash:~# mkdir go-demo && cd go-demo
root@bash:~/go-demo# go mod init example.com/go-demo
root@bash:~/go-demo# go get github.com/google/uuid@v1.6.0
root@bash:~/go-demo# go install golang.org/x/tools/cmd/goimports@v0.30.0
root@bash:~/go-demo# goimports -version

For an App Store Go module, install or request the app first, then use the module path and version shown on its page. The server-managed mirror lets the Go REPL use that module without downloading it again.

Rust crates and tools

In the Rust REPL (evcxr), add a library with :dep. In Bash, cargo install builds and installs a command-line program. Cargo's downloads and build output use scratch; installed executables go in ~/.cargo/bin.

evcxr> :dep serde_json = "1"
evcxr> serde_json::json!({"ok": true})
Object {"ok": Bool(true)}
root@bash:~# cargo install --locked ripgrep@14.1.1
root@bash:~# ~/.cargo/bin/rg --version

App Store Rust crates are mirrored by the server. After enabling an app such as serde_json, use its :dep line in evcxr as shown on the app page.

Java libraries with Maven

Maven is available in Bash. Its local repository is in the terminal's scratch area. This example downloads Apache Commons Lang and starts JShell with the jar on its class path:

root@bash:~# mvn -q dependency:get -Dartifact=org.apache.commons:commons-lang3:3.17.0
root@bash:~# jshell --class-path "$OPENREPL_SCRATCH/cache/m2/org/apache/commons/commons-lang3/3.17.0/commons-lang3-3.17.0.jar"
jshell> import org.apache.commons.lang3.StringUtils;
jshell> StringUtils.capitalize("hello")
$1 ==> "Hello"

You can also enable an App Store Java jar such as commons-lang3; OpenREPL adds enabled jars to JShell's class path automatically.

Ubuntu packages and apt

Do not run apt install in an OpenREPL Bash terminal. The system image is protected, and changes made to it would not be a per-user install. For curated Bash tools such as git or ripgrep, install them from the App Store; its apt installer creates a sandboxed bundle. If you operate the server and need a package built into every image, add it to the image's prerequisite install script and rebuild the image.

# Server image only (Dockerfile or prerequisite script)
RUN apt-get update && apt-get install -y --no-install-recommends maven libwww-perl

After enabling ripgrep from the App Store, run the tool in Bash:

root@bash:~# rg --version
ripgrep 13.0.0

Verify tools and proxy access

Check the versions installed in this image. These can change when the server image is updated. Scratch paths vary by workspace.

root@bash:~# node --version
root@bash:~# npm --version
root@bash:~# java --version
root@bash:~# mvn --version
root@bash:~# perl -MLWP::UserAgent -e 'print "LWP::UserAgent OK\n"'
root@bash:~# printf 'CARGO_HOME=%s\nCARGO_TARGET_DIR=%s\nCARGO_INSTALL_ROOT=%s\n' "$CARGO_HOME" "$CARGO_TARGET_DIR" "$CARGO_INSTALL_ROOT"

When Internet for REPLs is enabled, this Node request uses the configured environment proxy. It checks proxy access, not direct outbound networking. npm view is a quick registry check.

root@bash:~# NODE_USE_ENV_PROXY=1 node -e '
const https = require("node:https");
const req = https.get("https://example.com", res => { console.log("HTTPS status:", res.statusCode); res.resume(); });
req.setTimeout(10000, () => req.destroy(new Error("timeout")));
req.on("error", e => { console.error(e.code || e.message); process.exitCode = 1; });
'
root@bash:~# npm view lodash version

cargo install puts its registry and build cache in Scratch; CARGO_INSTALL_ROOT points to the home directory for installed commands. A PCRE2-unavailable notice from ripgrep is optional-feature information if rg --version succeeds. On Java 21, an old Maven quickstart may fail because it targets Java 5; for that legacy project, build with mvn -q -Dmaven.compiler.source=8 -Dmaven.compiler.target=8 package.

If a package is missing, search the App Store or request it from an administrator. For project dependencies, use the matching language package manager instead.
